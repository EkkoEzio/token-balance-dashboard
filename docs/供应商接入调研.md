# 各供应商接入调研结论

日期:2026-08-10
用途:记录各家 API/接口的调研结论,供后续接入和维护参考。

---

## 1. DeepSeek(已接入 ✅)

- **类型**:余额型(RMB),无时间窗口
- **取数**:`GET https://api.deepseek.com/user/balance`
- **鉴权**:`Authorization: Bearer <API_KEY>`
- **响应字段**:
  ```json
  {"is_available": true, "balance_infos": [{"currency":"CNY","total_balance":"110.00","granted_balance":"10.00","topped_up_balance":"100.00"}]}
  ```
- **特点**:公开 API,最稳定,无风控风险
- **文档**:https://api-docs.deepseek.com/zh-cn/api/get-user-balance

## 2. 智谱 BigModel Coding Plan(已接入 ✅)

- **类型**:窗口型(5小时滚动 + 7天),单位「积分 credits」
- **取数**:`GET https://open.bigmodel.cn/api/monitor/usage/quota/limit`
- **鉴权**:`Authorization: <API_KEY>`(**注意:不加 Bearer 前缀**)
- **关键发现(实测,非文档)**:
  - 窗口类型是 `CREDIT_LIMIT`(不是社区文档说的 `TOKENS_LIMIT`,那是旧版)
  - `unit` 字段区分窗口:`3`=5小时,`6`=7天
  - `nextResetTime` 是**毫秒时间戳**(不是 ISO 字符串),需 `/1000` 转 ISO
  - 业务层错误码:HTTP 200 但 body `code:401` 表示 key 过期(code 字段在 body 里,不在 HTTP status)
- **响应字段**:
  ```json
  {"code":200,"data":{"level":"lite","limits":[
    {"type":"CREDIT_LIMIT","unit":3,"usage":2000,"currentValue":300,"remaining":1699,"percentage":15,"nextResetTime":1786257130291},
    {"type":"CREDIT_LIMIT","unit":6,...}
  ]}}
  ```
- **各档位额度**(参考):
  | 档位 | 5h 积分 | 7d 积分 |
  |---|---|---|
  | Lite | 2,000 | 10,000 |
  | Pro | 12,000 | 60,000 |
  | Max | 28,000 | 140,000 |
- **坑**:推理必须用 `/api/coding/paas/v4` 端点才扣套餐额度;monitor 接口非官方,无 SLA

## 3. Tavly(已接入 ✅,国内需特殊处理)

- **类型**:用量/总量型,每月1号重置,支持多账号(多 key)
- **取数**:`GET https://api.tavly.com/usage`
- **鉴权**:`Authorization: Bearer <API_KEY>`
- **响应字段**:
  ```json
  {"key":{"usage":150,"limit":1000},"account":{"current_plan":"Researcher","plan_usage":184,"plan_limit":1000,...}}
  ```
  - remaining = plan_limit - plan_usage(plan_limit 为 null 表示无限)
  - 无 reset 时间字段(规则:每月1号重置)
- **国内网络问题(重要)**:
  - `api.tavly.com` 被 Clash fake-ip 拦截(分配 198.18.x.x,但规则判直连 → SSL EOF)
  - Tavly 的 DNS(`ns1.eftydns.com`)极不稳定,全球 DNS 间歇性 NXDOMAIN
  - **解决方案**(已实现,见 `providers/tavly.py`):
    1. 域名请求失败(被墙)→ Google DoH(`8.8.8.8/resolve`)解析真实 IP,走本地 Clash 代理
    2. DoH 也失败 → 用硬编码的 AWS 真实 IP 兜底(`_FALLBACK_IPS`)
    3. 用 `真实IP + Host头 + 本地代理` 请求,绕过 fake-ip
  - 已知真实 IP(2026-08 抓取,定期更新):`52.206.237.53`、`52.44.243.183`、`100.25.28.241`
- **依赖**:本地 Clash 开着(探测 7890/7891/7892 端口)
- **文档**:https://docs.tavily.com/documentation/api-reference/endpoint/usage

## 4. 千问 Token Plan(待接入 ⏳)

- **类型**:窗口型(5小时 + 7天),单位「Credits」
- **登录态**:在 platform.qianwenai.com(IAB/Edge 登录),**无公开 API**
- **已找到的 API 路径**(从 JS bundle `billing.js` 逆向,未经实测):
  - API host:`platform-api.qianwenai.com`
  - 用量:`/tokenplan/personal/api/v2/usage`(zeldaHttp 网关: `zeldaHttp.apikeyMgr./tokenplan/personal/api/v2/usage`)
  - 额度配置:`/tokenplan/personal/api/v2/quota-config`
  - 加油包:`/tokenplan/personal/api/v2/addon/list`
  - 订阅:`al/api/v2/subscription`
- **鉴权**:需登录态 token(在 SPA 的 session storage,非 cookie),**后端读不到**
- **接入障碍**:
  - 公开 API 无
  - IAB 的 cookie 库读不到登录态(千问用 token 鉴权,登录态在 sessionStorage)
  - IAB 的 `evaluate`(执行 JS)被 Chromium 安全策略禁用,无法在页面内发请求抓响应
  - `platform-api` 跨域 + token 头,直接导航拿不到 JSON
- **唯一可行路径**:用户在 Edge 手动抓包(DevTools Network),把接口的 URL + Response 复制出来,确认字段后接入
- **抓包步骤**:见 `docs/superpowers/specs/` 对话记录(千问 token-plan 页面 F12 → Network → 搜 tokenplan → 刷新 → 复制 URL+Response)
- **套餐信息**(文档):
  | 档位 | 5h Credits | 7d Credits |
  |---|---|---|
  | Lite | 700 | 2,500 |
  | Standard | 3,000 | 10,000 |
  | Pro | 12,000 | 40,000 |
- **注意**:5 小时限额「当前限时取消」(文档原文,可能随时恢复)

## 5. MiniMax Token Plan(待接入 ⏳)

- **类型**:窗口型(5小时 + 7天)+ 月订阅,单位「次数 requests」
- **已知的 API 端点**(社区逆向,鉴权有矛盾):
  - 旧版:`GET https://www.minimaxi.com/v1/token_plan/remains`(Bearer API Key)
  - 新版:`GET https://www.minimaxi.com/v1/api/openplatform/coding_plan/remains`(实测返回 "cookie is missing")
- **响应字段**(旧版,来自社区):
  ```
  current_interval_total_count / current_interval_usage_count / current_interval_reset_time(5h窗口)
  current_weekly_total_count / current_weekly_usage_count / current_weekly_reset_time(周窗口)
  model_remains[](模型拆分)
  ```
  新版字段漂移:旧 count 字段恒为 0,改用 `current_interval_remaining_percent` / `current_weekly_remaining_percent`
- **鉴权矛盾**:官方文档写 Bearer Key,但 `/coding_plan/remains` 实测要 cookie;且必须用 Token Plan 的 Subscription Key(`sk-cp-` 开头)
- **接入障碍**:与千问类似,需登录态/cookie,鉴权方式不确定
- **唯一可行路径**:用户手动抓包确认接口和鉴权方式
- **各档位**(参考):
  | 档位 | 月付 | 5h 次数 |
  |---|---|---|
  | Starter | ¥29 | 600 |
  | Plus | ¥49 | 1,500 |
  | Max | ¥119 | 4,500 |
- **文档**:https://platform.minimaxi.com/docs/token-plan/faq

## 架构备忘

- **能直接接的**(公开 API + Key):DeepSeek、智谱、Tavly
- **需登录态的**(无公开 API,靠 cookie/token):千问、MiniMax → 目前只能占位
- **后端读 Edge cookie**:`cookie_jar.py` 用 yt-dlp cookiesfrombrowser(复用 B站项目模式),但千问/MiniMax 的登录态不在 cookie 里,这条路对它们无效
- **IAB 自动抓包失败原因**:evaluate 全禁 + 登录态在 sessionStorage + 跨域限制
